# 刻度首次使用教程

[English](GETTING_STARTED.md) · [返回首页](../README.zh-CN.md) · [下载安装包](https://github.com/Akenaiai/codex-gauge/releases/latest)

适用于 Windows 0.4.6。TapNow 改为已有主页按需读取，Ideogram 仍待真实平台验证。刻度保留原 Codex 小仪表，并提供统一的 AI 额度中心。**不需要注册刻度账号，也不需要在刻度里额外登录各个平台。** 查询沿用你自己电脑上的已有连接。Runway/Recraft 可从刻度打开官方浏览器授权，MiniMax 国际站可填写 Subscription Key；其他工具按对应指引在原客户端或 CLI 完成登录，也可以先跳过。

## 首次连接

Windows 0.4.6 提供可接续的平台选择、逐平台连接说明、可跳过会员备注和隐藏恢复。有效当前读数自动进入看板，明确隐藏会保留。详见[首次连接](NEW_USER_CONNECTIONS.zh-CN.md)。稳定版 0.4.6 下载已包含此流程。

## 1. 安装并打开

1. 打开上方发布页，在 **Assets** 下载 `Codex.Gauge.Setup.0.4.6.exe`。需要免安装运行时选 `Codex.Gauge-0.4.6-win.zip`，完整解压后运行其中的 `Codex Gauge.exe`。后续版本以发布页文件名为准。GitHub 的 **Source code** ZIP 是源码，需要开发环境才能运行。
2. 系统要求是 Windows 10/11 x64。安装包已包含桌面运行环境，无需另装 Node.js；可选的 Agent Relay 查询需要另外安装该工具及 Python。
3. 当前安装包没有 Windows 代码签名。可将下载文件右键复制路径，在 PowerShell 运行 `Get-FileHash -Algorithm SHA256 -LiteralPath '下载文件的完整路径'`，与同一发布页的 `SHA256SUMS.txt` 比较。这只能验证文件是否一致，不等于代码签名；不要关闭系统保护。
4. 运行刻度。从任务栏通知区域的刻度图标打开 **额度中心 · 全部 AI 工具**；图标可能收在隐藏图标菜单中。已有 Codex 小面板也有进入额度中心的按钮。

原 Codex 小仪表需要 Codex 桌面客户端和已经安装、登录的[官方 Codex CLI](https://github.com/openai/codex)。登录由官方工具管理，刻度无需额外的 Codex API Key。打开 Codex 后小仪表会尝试跟随头像；没有显示时先从托盘打开。Mac 仅有未实机验证的源码悬浮预览，没有对应的已验证安装包。

## 2. 第一次看什么

1. 第一次打开会先显示引导，列出发现的工具、查询入口和已读到的余额。可以跳过，之后从顶部 **使用引导** 重看；旧安装升级不自动弹出。在 **全部工具** 查看发现依据，例如 CLI、MCP 配置、插件或仅安装缓存。目录只说明本机发现了什么，不代表每项都已登录或有余额查询接口。
2. 对已有查询适配的工具，打开 **查看 / 详情 → 刷新**，核对账户、来源和读取时间。缺少连接时按下方表格处理。没有适配的工具可用 **补充记录**，记录会标为“本人记录”。
3. 回到 **额度总览**，先用四个筛选判断要用什么。

| 筛选 | 怎么理解 |
| --- | --- |
| 有额度 | 当前有效读数显示仍有可用额度；不同平台单位、账号分别看 |
| 已用尽 | 当前有效读数确认已用尽；未知数据不会当作零 |
| 临期 / 快重置 | 7 天内到期或 2 天内重置，可与前两种状态重叠；重置卡到期会单独注明 |
| 待确认 | 未读取、失败、过旧或周期已过，需要刷新核实 |

点击 **详情 → 日期与来源** 看完整积分池和读取时间；在 **到期与恢复** 看日历。不同账号的余额不会自动合并，网页记录也不会自动认作 API 查询的同一个账号。刚装好的刻度不带开发者的账户、余额或日期规则；没有发现受支持的本机来源时，列表可能为空。截图中的数据均为合成示例。

### 切换额度看板

在标签页预览版中，悬停展开小仪表后默认显示 **Codex**，点 **编程工具** 或 **创作积分** 标签切换。Windows 上点小窗外即可收起，点击徽章固定后也一样；重新打开回到 Codex。创作页刷新只查创作来源，完整分项和日期填写继续在额度中心。

在 Windows 的 Cursor 客户端打开 **设置 → Plan & Usage**，保留该页面，再选刻度的 **编程工具** 或刷新 Cursor 卡片。预览版通过 Windows 辅助功能读取客户端显示的 **Cursor Models** 和 **Other Models** 用量条，以及页面提供的重置日期，沿用 Cursor 中已经登录的会话。读不到时，本次运行内的旧读数会标为上次读取。额度中心已有受支持的套餐百分比时，其他编程工具也会出现在这里。

在刻度设置中开启 **隐藏 Cursor**，编程工具看板会隐藏 Cursor 并暂停读取。关闭该开关即可重新显示。

Windows 源码预览支持 Qoder。点 Qoder 左下角的 **查看我的用量**，保持用量面板打开，再切到刻度的 **编程工具**。刻度通过 Windows 辅助功能读取客户端显示的积分，按分项显示剩余和总量，并显示客户端提供的续期日或有效期。需要向 Qoder 请求最新数据时，先点 Qoder 面板内的 **刷新用量**，再用刻度的 **刷新编程额度**重读。

Windows 源码预览也支持读取 Devin Desktop 自带的 CLI。用 `devin auth login` 完成一次 CLI 登录后，打开 **编程工具**。刻度在独立会话中运行只读 `/usage`，显示有返回的日／周额度、重置时间和额外用量余额。CLI 只给出倒计时时，重置时间会标为「约」。刻度沿用 CLI 自己的登录，读数留在内存中。面板打开时约每分钟刷新一次。

在 **编程工具** 中，Kilo 以美元显示当前 Kilo Gateway 的积分余额。个人账户还会自动识别生效中的 Kilo Pass 和商城订阅。Kilo Pass 显示本期剩余额度（包括官方返回的奖励额度），有下次账单时间时一并显示。商城套餐按用量窗口显示剩余百分比，以及官方提供的重置时间。选中团队时读取团队余额。刻度沿用本机的 Kilo 登录，Kilo 窗口可以关闭。打开此标签页时约每分钟刷新一次，也可点击 **刷新编程额度**立即查询。读数只留在内存中，刻度不复制登录凭据。

编程工具页在可滚动列表上方固定显示彩色状态和计数。剩余大于 10% 至 20% 用黄标，剩余大于 0% 至 10% 用红标，确认归零用实心红标。已知具体时间时，重置前两小时用蓝色倒计时；只有日期时，当天用蓝色「今天重置」。同一项可同时显示余量和重置提示。旧读数置灰，不计入当前提醒。**刷新编程额度**会重试 Cursor、Qoder 和已连接且支持查询的编程工具。

7天内到期标红置顶，24小时内或只有日期且今天到期时加强边框；用尽置灰排后。到期与预计恢复可同时倒计时，只有日期就按天 / 今天显示，不编造时刻；悬停可看完整日期与来源。预计时间到了仍需核实到账。部分赠金到期会注明分项数量，不代表总额都要到期；旧读数或未匹配账号的日期继续待确认。

每日赠送、当天清零的积分保留余额和日期，但不作到期通知、标红置顶或创作页到期倒计时。并非所有“今天到期”都静音，月度 / 购买积分仍正常提醒。在填写日期时，只有对应这类每日池才选“每日赠送（当天清零）”，表单会说明到期静音。

## 3. 会读取哪些本机连接

CLI 是命令行工具，MCP 是供 AI 客户端调用的工具连接，插件是客户端扩展。同一个平台可以同时有几种接入方式；看到多个入口不代表拥有多份额度。

读取范围是**运行刻度的当前系统用户环境**：常见客户端配置、已知工具安装位置和当前进程环境变量。它不做全盘扫描，不主动查找其他系统用户、其他电脑或全部云端账号。自定义位置、浏览器专用服务、宿主托管 OAuth 连接可能无法自动发现或复用。

| 本机来源 | 用于什么 |
| --- | --- |
| Codex、Claude Code / Desktop、Cursor、Gemini CLI、Qwen Code、OpenCode、Windsurf 常见配置 | 提取 MCP / 插件名称、启用状态等目录信息；被发现不代表已登录或能查额度 |
| PATH 与常见用户工具目录 | 查找已知 CLI，不执行任意发现的 MCP 启动命令 |
| `~/.codex/skills`、`~/.agents/skills`、Codex 插件缓存 | 判断相关工具的安装线索；缓存不代表启用，也不代表连接可用 |
| 当前进程的对应 API 环境变量、对应且已启用的 MCP 配置 | 为已支持的 API 适配读取凭据；OpenCode / Windsurf 当前仅参与目录发现，不复用其 API Key |
| 当前用户可选的本机加密凭据和私人导入文件 | 读取自己保存的 API 连接、宿主快照或日期记录；安装包不附带这些数据 |

已支持的自动余额查询如下。其他工具会保留在目录中，不能保证每个都有自动查询。

| 工具 | 查询所需连接 | 日期边界 |
| --- | --- | --- |
| Codex | 已登录的官方 CLI，本机 app-server 只读查询 | 只展示接口实际返回的窗口、重置及卡片日期 |
| 小云雀、即梦 | 原工具已安装且已登录的原生 CLI | 当前余额响应没有积分到期 / 发放日 |
| Lovart | Codex 中已有且可用的 Lovart MCP 连接 | 仅固定余额工具，当前响应不提供账号身份和日期 |
| Suno | Codex 中已有且启用的 `suno` MCP 连接 | 生成积分与下载额度分开；会员续期仅作账期；无稳定账户ID |
| Kimi、MiniMax | 另行安装的 Agent Relay 与 Python、对应已有连接 | 以接口返回为准；缺少伴随工具时不会自动安装或派任务 |
| ZCode / 智谱中国站 | 在刻度中填写本人编程套餐 API Key，核验成功后加密保存 | 返回的周期余量和重置时间 |
| Firecrawl、Tavily、DeepSeek | 对应 API 凭据 | 接口日期与规则推导分开，余额不一定有到期日 |

Runway、可灵、Recraft复用Codex中的官方会员MCP。已有连接和授权可直接用；没有时，在原Codex配置下列官方地址并在浏览器完成一次正常授权：

```sh
codex mcp add runway --url https://mcp.runwayml.com/mcp
codex mcp add kling --url https://klingai.com/mcp
codex mcp add recraft --url https://mcp.recraft.ai/mcp
```

使用原会员账号，选择有积分的工作区。已有同名配置时用 `codex mcp login <名称>` 恢复授权，不覆盖原条目。刻度不新增登录框或复制平台会话，只调用账户余额工具；OAuth范围以官方授权页列出为准。开发者API余额独立，不拿来代替会员积分。Recraft目前只支持明确的当前个人账户摘要，未知/团队格式保持待确认；可灵未配置MCP时仍可复用原CLI，但MCP失败不切到另一个CLI账号。见[连接详情](releases/0.3.13.md)。

订阅表中的发放日可作为独立月度预计保存，无需先接通余额。冲突留待核对，保留现有规则；每月套餐量不当剩余余额，公式算出的会员结束日不当已核实的积分到期日。

Firecrawl、Tavily、DeepSeek 可以复用当前进程的 `FIRECRAWL_API_KEY`、`TAVILY_API_KEY`、`DEEPSEEK_API_KEY`，或 Codex / Cursor / Claude / Gemini / Qwen 的对应已启用 MCP 配置中的变量。Windows 的 Firecrawl 和 DeepSeek 查询还支持当前用户 `~/.codex/private/credentials/<provider>-api-key.dpapi`。这些是可选读取路径，不要求创建这些文件。

没有已有 API 连接时，可自愿使用 **详情 → 连接查询** 输入自己的 API Key。刻度先验证只读查询，再用本机系统加密保存；这不是平台账号登录，也不会创建 Key、购买套餐或扩大权限。也可以不填写，保留待确认状态。不要把 Key、Cookie、配置文件或真实额度截图发到公开 Issue。

### 可选的 TapNow / Ideogram 网页连接

11月16日源码更新已接入TapNow官方免费余额查询，沿用Codex已有连接，下面的网页方式作为后备；0.4.7安装版仍沿用网页方式。Ideogram继续使用网页读取。0.4.4 提供可选浏览器组件：**全部工具 → 查看 → 连接网页余额**。在 Chrome / Edge 加载组件并本机配对；TapNow 复用正常打开的主页，读取固定余额和当前团队标识，不刷新、不保活，用完可关闭。Ideogram 仍需专用页和本人点选。上次积分与时间保留在额度中心。组件默认关闭，不在刻度里登录、不复制 Cookie 或会话；网页读数不验证账号归属，也不刷新日期。[完整安装与隐私说明](BROWSER_CONNECTION.zh-CN.md)。

## 4. 哪些日期是实查，哪些是预计

**每个日期都要看来源和核对时间。余额刷新成功，不代表网页日期也更新了。**

| 来源 / 标记 | 能说明什么 | 刷新方式 |
| --- | --- | --- |
| 自动查询中的日期 | 上次接口实际返回的该账户日期；未来恢复仍需到时查询 | 随支持的余额接口重新读取；失败保留旧读数并标记 |
| 网页账户、核对于、非实时 | 一次真实网页核对的历史记录，可能已变化 | 由用户在自己的浏览器核实并更新私人导入；刻度不登录网页；可选余额组件也不刷新这类历史日期 |
| 官方规则 / 依官方规则 | 按公开规则展示有效期或推导恢复日，不是到账凭证 | 可在详情查看规则来源和核对日期；规则说明不是实时政策服务 |
| 本人确认 | 用户填写的一次日期，准确性由填写者核对 | 详情中用“补充日期”修改；到时提醒核实 |
| 按月度同日规则预计、未确认到账 | 用户设置的每月预计发放日 | 随日历推进，支持修改或关闭；不会自动认定到账 |
| 日期未提供 / 日期未展示 | 当前来源没有足够信息 | 保持未知；不拿会员截止日或账单日代替 |

只有日期就不补具体时刻；页面未说明时区时保持未知。**积分到期、额度重置、会员到期、账期结束是不同事件。** 没有到期日也不代表永久有效，只有来源明确说明时才显示永久有效。

### 设置每月预计发放

在引导中点击工具旁的 **填写日期**，之后也可以从 **详情 → 本人日期与每月预计 → 填写日期** 进入。发现的非 Codex 工具都可以填写，暂时不能自动查余额也可以记录。无需配置文件或网页记录导入；Codex 日期继续由原小仪表管理。

1. 有已核实账号和积分池时，直接选择。否则选“单独记录一个账号”，填账号 / 工作区别名和积分池名称；MCP 身份未知时不会自动匹配。
2. 填积分到期日、每月发放日号，或两者都填。确认实际按月发放后，才选“按月发放的订阅积分”；充值积分、每日领取积分不套月度预计。
3. 保存后，总览、详情和日历都会显示本人日期或预计发放。每月 12 日就预计每月 12 日；31 日遇到短月取月底，之后恢复 31 日。预计不代表到账，也不会改写自动余额。
4. 点击“修改”可调整日期或提醒开关。“删除这条日期记录”会移除这条本人日期及其预计，自动余额和历史网页记录仍独立保留。

绑定已核实账号的日期在换号后暂停跟随原来源；单独记录保持独立，只提醒核实对应别名账号。一次到期日不会悄悄变成每月重复到期。旧版导入的网页记录及其控件仍可使用，[私人文件导入](CREDIT_CENTER.md#account-page-date-observations)只用于可选进阶集成。

## 5. 开启查询与提醒

在额度中心 **查询与提醒设置** 开启 **运行时自动查询** 和 **到期与恢复提醒**。自动查询默认每五分钟进行，手动刷新可随时使用。原 Codex 小仪表通常每分钟读取，其提醒仍由原仪表设置控制。

新平台已知到期可在 7 / 3 / 1 天提醒；Codex 余量 ≥30% 时，周额度从重置前 24 小时开始提醒，各周期另有 4、2、1 小时提醒。月度预计会在临近、当日及有限的逾期阶段提醒核实，**日期到了不会显示成已到账**。提醒按来源、账号及阶段去重；实际送达仍受 Windows 通知设置影响。

退出刻度、电脑休眠或关机期间暂停查询，重新运行后补查，不能保证补发每一条错过的通知。需要随 Codex 打开时，可在 Windows 安装版的原仪表设置启用 **随 Codex 启动**；新用户默认关闭，可随时关闭并移除相应当前用户任务。没有云端代查或跨夜服务。

## 6. 常见情况

| 情况 | 处理 |
| --- | --- |
| 提示“需要登录” | 在对应工具原来的官方客户端 / CLI 登录，然后回刻度刷新；无需在刻度输入密码或验证码 |
| 只看到插件缓存 | 先确认原宿主是否启用该连接，以及刻度是否有该平台适配 |
| 刚配置的工具没有出现 | 在“查询与提醒设置”点“重新梳理工具”；环境变量变更后重启刻度 |
| Lovart 有余额但没有日期 | 当前 MCP 不返回日期或账户身份；网页记录需独立核对，不能自动绑定 |
| API 刷新后网页日期没变 | 属于正常边界，网页记录是上次核对的历史记录 |
| 恢复日期已到但余额未变 | 查看预计 / 规则标记，再刷新对应来源核实；可能有领取条件或平台延迟 |
| 查询失败或数据过旧 | 保留上次记录并标待确认，检查网络及原连接，稍后刷新；失败不会变成零余额 |

## 数据保存与开源范围

设置、工具清单、余额、私人日期及提醒回执保存在刻度的当前用户数据目录；Windows 通常为 `%APPDATA%/Codex Gauge`，启动环境虚拟化可能使实际目录不同。可选 Key 保存在本机系统加密的 `credit-secrets.json`，普通余额记录不含 Key。不要分享整个数据目录，也不要把它当作绿色 ZIP 的可分发附件。

刻度不读取浏览器 Cookie 或聊天档案，不在刻度里提供平台登录框，不自动生成作品、花积分、充值、用卡或发模型请求。受支持的 CLI / MCP 查询沿用客户端原有认证；API 查询会向对应平台发送认证请求。原仪表还可访问匿名 AIHOT 公告，手动检查更新会访问 GitHub；没有刻度账号服务器或遥测。详见[数据与限制](../README.zh-CN.md#数据和当前边界)、[安全说明](../SECURITY.md)和[本次分发隐私核对](PRIVACY_VERIFICATION.md)。MIT 许可覆盖项目代码，第三方工具、服务和数据仍遵循各自规则。
