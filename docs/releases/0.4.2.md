# 0.4.2 — Bounded background page reads

TapNow now takes synchronous snapshots from its fixed account-menu balance and current-team fields. Sampling and short waits run in the extension worker, rather than waiting on timers inside the page. Every read has a deadline, busy reads still allow independent local heartbeats, and worker wakeups preserve an existing poll alarm. A stalled or late read cannot keep the connection busy indefinitely or send a result after its deadline.

The selected-field reader and picker also check the expected supported home page before touching the DOM and after asynchronous waits. Navigating to a working canvas invalidates that operation. Account markers remain unverified, different teams stay separate, and missing or expired readings never become zero. No browser permissions, provider credentials or embedded login flows are added.

204 automated checks, 73 packaged native checks and 18 installer-ASAR synthetic-user isolation checks pass. The Windows upgrade preserves pairing, settings, independent dates and the original Codex/card-flip behavior. A real 20-minute Windows background run completed 4 automatic updates with every sampled heartbeat connected and the final balance matching the creative back. No browser automation or agent-triggered manual refresh ran during that observation. Ideogram and Mac still need live field validation.

After installing this update, reload the existing component in Chrome/Edge's extension manager, confirm its title says **0.4.2**, and use **Open dedicated tab** again. Existing pairing is retained. Keep the browser and dedicated home page available; TapNow does not require point selection.

Background design references: Chrome waits for an injected Promise to settle ([scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting)), and recreating a same-name alarm replaces its schedule ([alarms API](https://developer.chrome.com/docs/extensions/reference/api/alarms)). The observed failure chain was reproduced with a stalled page script; the exact browser scheduling trigger in the earlier live incident was not independently established.

本人点选的读取和选取流程也会在访问 DOM 前、异步恢复后核对受支持的预期主页；转到工作画布就终止本轮操作。账户归属仍未验证，不合并不同团队，缺失和过旧读数不会变成零。不增加浏览器权限、平台凭据或刻度内登录流程。

204 项自动检查、73 项包内原生检查、18 项安装器实际代码的合成用户隔离检查通过。Windows 升级保留原配对、设置、独立日期及原 Codex 仪表 / 翻面行为。真实 Windows 后台连续 20 分钟完成 4 次自动更新，全部心跳采样在线，最终余额与背面一致；期间未自动操作浏览器，也未由执行者手动触发刷新。Ideogram 与 Mac 继续保留现场待验边界。

更新后在 Chrome / Edge 扩展管理页重新加载原组件，确认标题为 **0.4.2**，再点 **打开专用网页**；原配对继续使用。保持浏览器和专用主页可用，TapNow 无需点选位置。旧问题的代码故障链已通过挂起页面脚本复现，不把它写成已确认某种浏览器冻结机制。
