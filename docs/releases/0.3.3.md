# 0.3.3 — Account-page dates with honest precision

The overview and calendar can now supplement automatic balances with separately named, timestamped account-page date observations. These are one-time website readings: they do not merge account identities, overwrite a live balance, refresh automatically, or prove a credit grant. Expiry, expected renewal, billing/membership dates, permanent credits and dates not shown are kept separate.

Website clock text is preserved when shown, with an explicit unknown-timezone label. Date-only observations do not acquire invented epoch timestamps in MCP output. Rule-derived dates are marked, and conditional login gifts retain the requirement to sign in and claim. Approaching date reminders request verification; expiry messages cannot imply renewal. A zero-balance expiring pool does not trigger use-priority styling, while a zero-balance renewal can still request verification on its date.

DeepSeek's official help confirms that topped-up funds do not expire. The overview and purchased-pool details now say this directly, while grant expiry and fixed renewal remain unknown when not provided. Pippit, Dreamina and Lovart explain why their automatic balance paths omit dates. Private account-page observations remain outside source, packages and public screenshots.

Validation: 100 automated checks, including date precision, nickname escaping, independent account scopes, import corrections, reminders and MCP output; 27 native packaged-window interaction checks. Original badge and existing configuration are preserved. Natural future notification delivery and macOS retain their prior field-test limits.

## 简体中文

看板与日历新增独立的网页日期核对记录，保留账户名称、记录时间和非实时标识。它与自动余额分开，不自动合并账号，不覆盖实时余额，也不把预计日期写成已到账。

积分到期、恢复、会员/账单日期、永久有效和日期未展示分别表达。页面有钟表时间但没写时区时保留原文；只有日期就保持日期，MCP 不编造精确时间。依官方规则推导的日期与需登录领取的条件明确标注。网页提醒只请核实，到期提醒不冒充恢复；零余额到期不引导优先消耗，零余额恢复仍可在当日提醒核对。

DeepSeek 充值余额按官方说明标为永久有效，赠金有效期及固定恢复周期缺失时继续保持未知。小云雀、即梦、Lovart 的自动入口未返回日期时说明原因。真实账户分项和日期仅保存在本机，不进入公开源码和安装包。

100项自动检查与27项发行资源原生窗口检查。原小仪表与配置保留，自然未来通知和Mac继续待验。
