# 0.3.7: Expiry priority and creative countdowns

The creative face now places upcoming expiries within seven days first, ordered by deadline and highlighted in red. Known exact expiries within 24 hours, and date-only expiries due today, receive a stronger border. Confirmed used-up tools are gray and move to the end. An approaching renewal alone never receives expiry styling.

Expiry and expected-renewal countdowns can appear together, with pool names, expiring amounts and source/account context. Exact timestamps count down in days/hours/minutes. Date-only observations use calendar days or “today”; unspecified website timezones never acquire an invented hourly countdown. Absolute dates remain in the tooltip. A reached renewal stays a verification prompt, not an arrived-credit claim.

If only a bonus pool expires, the total is kept separate. The main amount turns red only when the expiry belongs to that same selected record and pool. Stale or independently recorded dates remain explicitly unconfirmed. Existing manual dates preserve their own source separately for expiry and renewal, including the full credit center.

No additional login, upstream query cadence, spending or notification behavior is introduced. Original Codex face, Suno connection and local preferences are preserved. Windows remains unsigned; Mac and natural future notification delivery retain their existing field-test limits.

## 中文

创作背面将 **7天内到期** 的积分置顶，按最近到期排序并标红；准确时间在24小时内、或只有日期且今天到期时，加强边框。已确认用尽的工具置灰排到最后，单纯快恢复不会标成到期。

到期与预计恢复可同时显示倒计时，保留积分池名、临期数量、来源及账号。准确时间按天 / 小时 / 分钟倒计时，只有日期就显示几天后 / 今天，不给未知时区补造小时数；悬停可看绝对日期。预计恢复日已过只提示核实，不宣称到账。

部分赠金到期不会把总额都标红，只有到期属于所示同一记录、同一积分池时才红主金额。旧读数与独立日期仍注明待确认，手填到期和恢复的来源分开，不互相污染。原Codex仪表、Suno连接、本机偏好保留，不增加登录、查询频率、消费或通知行为。

安装包仍未签名，Mac与自然未来通知送达保留原待验范围。
