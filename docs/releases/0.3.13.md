# 0.3.13 — Direct member MCP refresh

- Runway now uses its official member MCP at `https://mcp.runwayml.com/mcp`, reusing the original Codex OAuth authorization. This replaces the unverified hosted-app bridge in 0.3.12. It reads actual workspace credits and keeps plan and purchased credits separate.
- Kling prefers its official MCP at `https://klingai.com/mcp`. It checks account identity around the fixed credit query and preserves zero. An explicitly configured MCP failure never falls back to a different CLI account; the existing CLI remains available only when no MCP is configured.
- Recraft supports the official MCP's personal-account text summary, including the currently returned plan. It checks both reported credit amounts and account identity, discards contact details, and rejects unverified structured/team formats rather than guessing.
- All three readers run through fixed read-only tools in ephemeral contexts. Hosted-app discovery, inference, generation and purchases are not used. Authorization remains in Codex or the original CLI; Gauge adds no provider login or copied session storage. Official authorization scopes are shown by the provider; Gauge only invokes the account tools described here.
- Monthly forecasts, conflict decisions and the original Codex badge are retained. Unsupported/unconfirmed balances stay in the center rather than the creative back.

Two consecutive live Windows reading rounds succeeded for all three providers. Synthetic tests separately cover UI, zero/error handling and account isolation. Windows packages remain unsigned; Mac and natural future notification delivery retain their existing field-test limits.
